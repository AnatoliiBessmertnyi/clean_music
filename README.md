# clean_music

Python CLI для очистки музыкальных тегов и имён файлов, нормализации исполнителей,
переименования и обработки предполагаемых дубликатов.

## Состояние и ограничения

При конфликте целевого имени оба файла сохраняются. Поиск предполагаемых
дубликатов только показывает кандидатов: автоматическое удаление и объединение
отключены, размер и качество имени не используются для выбора сохраняемой копии.

Изменения поддерживаются только из Windows на локальном NTFS. При сканировании
выбранного каталога допускаются обычные файлы с одной жёсткой ссылкой. Symlink
(включая битые), reparse points, каталоги с аудиорасширением и объекты с ошибкой
проверки пропускаются с причиной. Ссылки и reparse points в пути каталога
тоже приводят к отказу.
Переименование выполняется одним Windows `rename()` внутри каталога без замены
существующей цели. Смена регистра проверяется по фактическому написанию записи
каталога; временные имена не используются. Неподдержанные действия пропускаются
с причиной. В POSIX, включая WSL `/mnt/d`, изменения и их моделирование временно
отключены: «Модификация на монтированных файловых системах WSL временно отключена
из соображений безопасности» (POSIX не подтверждён). Чтение и показ кандидатов доступны.

Отказ изменения блокирует дальнейшие изменения по исходному пути до конца сессии;
при неопределённом результате переименования блокируется также целевой путь.
Уже записанные перед отказом переименования теги не откатываются.

При сканировании сохраняются идентификаторы тома и файла. Перед переименованием
и записью тегов приложение повторяет проверку исходника и родительского пути.
Если к моменту последней проверки видна подмена или безопасность исходника
не подтверждается, действие пропускается. При модельном переименовании dry-run
проверяется физический исходник. Между последней проверкой и файловой операцией
остаётся окно гонки. Отдельная цель переименования, включая битую ссылку, считается
занятой. Windows rename отказывает и при появлении отдельной цели после проверки.

Запись тегов через проверяемую рабочую копию и аварийное восстановление
запланированы. Безопасный и глубокий режимы пока недоступны. Их поведение
определяет [контракт двух режимов](docs/architecture.md#контракт-двух-режимов).
Для знакомства используйте отдельную папку с тестовыми копиями. Исходную
коллекцию следует сохранять независимо от программы.

Другие известные ограничения:

- Обрабатывается только выбранная папка, без рекурсивного обхода.
- Изменяются прежде всего исполнитель и название; объединения всех метаданных
  между копиями нет.
- Содержательные уточнения в скобках могут удаляться, в том числе автоматически
  из тегов при наличии символов, недопустимых для имени файла. Разные версии
  записи после очистки могут ошибочно попасть в одну группу дубликатов.
- `--dry-run` моделирует изменения тегов и переименования без их применения.
  Полная сверка прогноза с реальным запуском, включая итоговую статистику,
  остаётся задачей [#22](https://github.com/AnatoliiBessmertnyi/clean_music/issues/22).
- Отсутствие тегов, неполная пара «исполнитель — название» и ошибки чтения
  не всегда различаются. Запись тегов выполняется непосредственно в файл.
- Ответы меню и свободный ввод через `ConsoleInteractor` приводятся к нижнему
  регистру. Путь запрашивается отдельно через `get_valid_path()` и сохраняет регистр.
  Ручной ввод исполнителя на последнем этапе переименовывает файл, но сам по себе
  не записывает теги.

Принятые направления исправления и их статус описаны в
[архитектуре](docs/architecture.md). Они не являются возможностями текущей версии.

## Требования и установка

Требуется Python **3.13 или новее**. `.python-version` выбирает Python 3.13;
uv загрузит его при отсутствии. Зависимости и настройки определены в
`pyproject.toml`, разрешённые версии — в общем для Windows и Linux `uv.lock`.
Приложение запускается из исходного каталога без установки проекта как пакета
(`tool.uv.package = false`).

Один checkout на NTFS используется из двух ОС, но окружения физически раздельны.
Не используйте Windows-окружение из WSL и наоборот. Следующие переменные действуют
в текущей сессии; задавайте их перед работой в новой оболочке. Активация venv
не требуется; если старое окружение активировано, сначала выполните `deactivate`.

### Windows (PowerShell)

Если uv отсутствует, установите его через имеющийся Python без изменения PATH
и политики выполнения PowerShell:

```powershell
python -m pip install uv --target "$env:LOCALAPPDATA\clean_music\uv-bootstrap"
```

Из корня репозитория:

```powershell
$uv = "$env:LOCALAPPDATA\clean_music\uv-bootstrap\bin\uv.exe"
$env:UV_PROJECT_ENVIRONMENT = "$env:LOCALAPPDATA\clean_music\.venv"
& $uv sync --locked
& $uv run --locked python main.py
```

Если uv уже установлен, вместо `& $uv` можно использовать `uv`.

### WSL2 (Bash)

Если uv отсутствует, установите его без изменения профиля и PATH:

```bash
curl -LsSf https://astral.sh/uv/install.sh | env UV_NO_MODIFY_PATH=1 sh
```

В том же репозитории на NTFS (путь при необходимости скорректируйте):

```bash
cd '/mnt/d/Program Files/Dev/clean_music'
export PATH="$HOME/.local/bin:$PATH"
export UV_PROJECT_ENVIRONMENT="$HOME/.cache/clean_music/.venv"
uv sync --locked
uv run --locked python main.py
```

PATH здесь меняется только для текущей сессии. Старое окружение не удаляйте,
пока новая схема не проверена. `sync` по умолчанию включает группу разработки;
для окружения только приложения используйте `uv sync --locked --no-dev`.
Выбирайте выделенный путь: точная синхронизация удаляет лишние пакеты из него.

`uv lock --check` проверяет актуальность lock-файла. Обычная работа использует
`--locked`: несоответствие конфигурации завершится ошибкой без перезаписи lock.
После согласованного изменения зависимостей выполните `uv lock`, проверьте diff
и зафиксируйте `uv.lock` вместе с `pyproject.toml`. Обновление через
`uv lock --upgrade` выполняется только как отдельное согласованное действие.
Справка: [установка uv](https://docs.astral.sh/uv/getting-started/installation/),
[синхронизация](https://docs.astral.sh/uv/concepts/projects/sync/).

## Запуск

Из корня репозитория:

```powershell
uv run --locked python main.py
uv run --locked python main.py --dry-run
uv run --locked python main.py --debug
```

Программа интерактивно запрашивает путь к папке и решения по обработке.
Сухой режим имеет перечисленные выше ограничения и не доказывает безопасность
последующего применения изменений.

### Отчёт каждого запуска

CLI автоматически создаёт **один UTF-8 файл** `logs/run-<время UTC>-<id>.log`
рядом с `main.py`. Путь показывается перед запросом папки и после итоговой сверки.
Вопросы и предложения остаются в терминале; весь диалог, исходные ответы,
выбранные значения по умолчанию, выполненные операции, ошибки и итог сохраняются
в этот же файл. Его можно целиком передать на разбор. `logs/` исключён из Git;
отчёт содержит локальные пути и значения тегов.

До обработки и после неё программа читает SHA-256 и теги исполнителя/названия
аудиофайлов выбранной папки с диска, независимо от кэша конвейера. Большая папка
потребует времени на два полных чтения. Рекурсивного обхода нет; прочие расширения
не проверяются. Ссылки и reparse points не читаются, ошибки проверки фиксируются.

После успешного запуска и полной сверки в начале того же файла появляется
компактный отчёт v3: статус и полнота проверки, режим, commit (или `unknown`, если
Git недоступен), Python/платформа, длительности обработки и сверки, счётчики файлов.
Проблемы показываются первыми: исчезновения, ошибки, отказы и блокировки с причинами,
в том числе «теги записаны, rename отклонён». Для изменённых файлов показаны
дельты имён и artist/title; при переименовании и изменении содержимого без дельты
artist/title показывается пометка `[содержимое]`. Счётчики включают нулевые значения.
Неизменённые перечислены по именам. Структурированные
события связываются с исходными файлами по цепочкам переименований и identity снимков.

Статусы файлов: не изменён, переименован, изменено содержимое/теги, оба изменения,
отсутствует после запуска, появился или ошибка проверки.
Файл, отсутствующий после запуска, не объявляется удалённым приложением:
текущий конвейер не выполняет удалений. Замена файлового объекта и ошибки чтения
не считаются подтверждением неизменности. Неполные теги показываются с пустым
полем; отсутствие тегов — `null`, ошибки чтения — в `errors`.

В приложении сохранены диалог, структурированные события и объединённые записи
файлов со снимками до и после: полные пути, identity, теги, ошибки и SHA-256.
Структурированные записи представлены JSONL; снимки отдельно не дублируются.
В dry-run события с пометкой `ПРЕДЛОЖЕНИЕ` отделены от факта диска, включая
блокировки модели. Счётчики конвейера не являются итогом сверки файлов и могут
учитывать несколько операций над одним файлом.

Во время работы журнал дописывается без перезаписи. При Ctrl+C, EOF или исключении
он сохраняется и выполняется доступная сверка; остаётся сырой формат с пометкой
прерывания/неполноты. Компактизация не запускается и при неполной сверке.
После успеха файл переформатируется через временный файл в `logs/` и замену
исходного отчёта. При ошибке компактизации остаётся исходный сырой журнал с
предупреждением; временный файл удаляется, если файловая система позволяет.
Принудительное завершение процесса, сбой питания или потеря диска могут оставить
только начатый журнал без итогов. Если лог невозможно создать, обработка не начинается;
ошибка записи журнала прерывает запуск. Отчёт не является резервной копией и не
откатывает изменения. SHA-256 всего файла меняется при записи тегов и не проверяет
аудиопоток отдельно; правильность текста тегов и защиту от конкурентных изменений
другими программами отчёт не гарантирует.

## Поддерживаемые форматы

Обработчики реализованы для MP3, M4A/MP4, FLAC, OGG Vorbis и WMA.
Поддержка расширения или контейнера не означает поддержку любого содержащегося
в нём кодека; для OGG используется обработчик Vorbis. Расширение само по себе
не определяет качество аудио.

## Текущий pipeline

Последовательно выполняются семь этапов:

1. Очистка мусорных вставок из имён и тегов.
2. Нормализация тире и пробелов в именах.
3. Нормализация `feat.`, разделителей и уточнений; переименование по тегам.
4. Запись тегов из распознанного имени файла.
5. Показ групп кандидатов в дубликаты без удаления и объединения.
6. Унификация вариантов регистра имён исполнителей.
7. Ручной ввод исполнителя для оставшихся файлов без распознанных тегов.

Оркестратор находится в `pipeline.py`, этапы — в `stages.py`.
Подробности компонентов и ограничения контракта путей — в
[описании реализованной архитектуры](docs/architecture.md#реализовано).

## Разработка и проверки

Основная рабочая среда — Windows; основной контур локальных проверок — отдельное
окружение Python в WSL. Команды ниже выполняются из корня после выбора
`UV_PROJECT_ENVIRONMENT` и `uv sync --locked`, описанных выше. В PowerShell
с установкой через pip заменяйте `uv` на `& $uv`.

```bash
uv run --locked python -m pytest tests/ -v
uv run --locked python -m ruff check .
uv run --locked python -m ruff format --check .
uv run --locked python -m mypy .
```

Файловые тесты должны использовать синтетические данные и временные каталоги.
Нынешние тесты проверяют отдельные функции именования и парсинга; надёжность
полного pipeline и аварийных файловых операций ими не подтверждена.
Исходники содержат подавления `type: ignore`; успех проверок нужно устанавливать
для конкретной ревизии и окружения, а не считать постоянным свойством проекта.

Правила работы Codex находятся в [AGENTS.md](AGENTS.md).
