# Audio Cleaner

CLI-скрипт для автоматической очистки и переименования аудиофайлов.

Приводит музыкальную коллекцию к единому стандарту: очищает мусорные теги,
нормализует имена исполнителей и названия треков, переименовывает файлы по
тегам и удаляет дубликаты.

## Возможности

- 🧹 Очистка от мусорных тегов и имён (vksaver, muzmo.ru и др.)
- 🏷️ Нормализация тегов (`feat.`, разделители исполнителей, уточнения в скобках)
- 📝 Переименование файлов по тегам и запись тегов из имени файла
- 🔍 Поиск и объединение дубликатов (с выбором лучшей копии)
- 👥 Нормализация написания имён исполнителей
- 🛡️ Интерактивная обработка недопустимых символов в именах
- ⚙️ Сухой прогон (`--dry-run`) и режим отладки (`--debug`)

## Установка

```bash
pip install -e .
```

Основная зависимость для работы с тегами — [`mutagen`](https://mutagen.readthedocs.io/).

## Использование

```bash
# Обычный режим
python main.py

# Сухой прогон (изменения не применяются)
python main.py --dry-run

# С отладочным выводом
python main.py --debug
```

## Этапы обработки

Обработка идёт последовательно, в 7 этапов:

1. 🧹 **Очистка от мусора** — удаление мусорных вставок из имён файлов и тегов.
2. ➖ **Нормализация тире и пробелов** — приведение разделителей и пробелов к единому виду.
3. 🏷️ **Переименование по тегам** — нормализация `feat.`, разделителей, уточнений в скобках и формирование имён из тегов.
4. 💾 **Запись тегов из имени файла** — для файлов без метаданных, но с корректным именем.
5. 🔍 **Поиск и объединение дубликатов** — автоматический выбор лучшей копии.
6. 👥 **Нормализация имён исполнителей** — объединение разных вариантов написания.
7. ⌨️ **Ручной ввод** — для файлов, оставшихся без метаданных.

## Архитектура

Код построен на паттерне **конвейера (Pipeline)**: каждый этап — независимый
класс, реализующий протокол `ProcessingStage`. `AudioProcessingPipeline`
последовательно передаёт список файлов от этапа к этапу.

Используемые подходы:

- **Pipeline** — оркестрация этапов обработки.
- **Dependency Injection** — контекст, репозиторий тегов и интерфейс взаимодействия
  передаются явно, что упрощает тестирование.
- **Strategy** — выбор способа обработки недопустимых символов.
- **Repository** — кэширование тегов для избежания повторного чтения с диска.
- **Строгая типизация** — код проходит `mypy` без ошибок и `# type: ignore`.

## Структура проекта

```
├── main.py              # Точка входа: сборка и запуск конвейера
├── config.py            # Регулярные выражения и настройки
├── pipeline.py          # Протокол этапа и класс конвейера
├── stages.py            # 7 конкретных этапов обработки
├── pipeline_utils.py    # Утилиты: переименование, поиск дубликатов
├── context.py           # SessionContext — состояние сессии и статистика
├── interactor.py        # Интерфейс взаимодействия с пользователем
├── tag_repository.py    # Чтение/запись тегов с кэшированием
├── naming.py            # Чистые функции нормализации имён
├── parsing.py           # Парсинг имён файлов
├── strategies.py        # Стратегии обработки недопустимых символов
└── tests/               # Модульные тесты
```
