# clean_music

Python CLI для очистки музыкальных тегов и имён файлов, нормализации исполнителей,
переименования и обработки предполагаемых дубликатов.

## Состояние и ограничения

Текущая реализация может безвозвратно удалять файлы. При конфликте целевого имени
`safe_rename()` выбирает сохраняемый файл по размеру и качеству имени, без проверки
идентичности аудио. При обработке выбранных групп дубликатов сохраняется самый
крупный файл. Размер не доказывает качество или совпадение записи.

Карантин, безопасная замена тегов через рабочую копию и аварийное восстановление
пока не реализованы. Для знакомства используйте отдельную папку с тестовыми копиями;
исходную коллекцию следует сохранять независимо от программы.

Другие известные ограничения:

- Обрабатывается только выбранная папка, без рекурсивного обхода.
- Изменяются прежде всего исполнитель и название; объединения всех метаданных
  между копиями нет.
- Содержательные уточнения в скобках могут удаляться, в том числе автоматически
  из тегов при наличии символов, недопустимых для имени файла. Разные версии
  записи после очистки могут ошибочно попасть в одну группу дубликатов.
- Некоторые этапы возвращают устаревшие пути после переименования. Пересканирование
  папки на поздних этапах не устраняет все последствия.
- `--dry-run` не записывает теги и не выполняет файловые изменения, но его модель
  путей и статистика неполны: прогноз следующих этапов может отличаться от запуска
  с применением изменений.
- Отсутствие тегов, неполная пара «исполнитель — название» и ошибки чтения
  не всегда различаются. Запись тегов выполняется непосредственно в файл.
- Консольный ввод приводится к нижнему регистру. Ручной ввод исполнителя на последнем
  этапе переименовывает файл, но сам по себе не записывает теги.

Принятые направления исправления и их статус описаны в
[архитектуре](docs/architecture.md). Они не являются возможностями текущей версии.

## Требования и установка

Требуется Python **3.13 или новее**, согласно `pyproject.toml`. Работа с аудиотегами
реализована через Mutagen. Зависимости и настройки инструментов определены в
`pyproject.toml`; `requirements.txt` содержит только `mutagen` и не описывает полное
окружение проекта.

Из корня репозитория, в выбранном виртуальном окружении:

```powershell
python -m pip install -e .
```

Для разработки:

```powershell
python -m pip install -e ".[dev]"
```

Список модулей упаковки сейчас неполон. Указанный способ рассчитан на работу
из исходного репозитория; установка собранного пакета вне него не подтверждена.

## Запуск

Из корня репозитория:

```powershell
python -m main
python -m main --dry-run
python -m main --debug
```

Программа интерактивно запрашивает путь к папке и решения по обработке.
Сухой режим имеет перечисленные выше ограничения и не доказывает безопасность
последующего применения изменений.

## Поддерживаемые форматы

Обработчики реализованы для MP3, M4A/MP4, FLAC, OGG Vorbis и WMA.
Поддержка расширения или контейнера не означает поддержку любого содержащегося
в нём кодека; для OGG используется обработчик Vorbis. Расширение само по себе
не определяет качество аудио.

## Текущий pipeline

Последовательно выполняются семь этапов:

1. Очистка мусорных вставок из имён и тегов.
2. Нормализация тире и пробелов в именах.
3. Нормализация `feat.`, разделителей и уточнений; переименование по тегам.
4. Запись тегов из распознанного имени файла.
5. Поиск предполагаемых дубликатов и обработка выбранных групп.
6. Унификация вариантов регистра имён исполнителей.
7. Ручной ввод исполнителя для оставшихся файлов без распознанных тегов.

Оркестратор находится в `pipeline.py`, этапы — в `stages.py`.
Подробности компонентов и ограничения контракта путей — в
[описании реализованной архитектуры](docs/architecture.md#реализовано).

## Разработка и проверки

Основная рабочая среда — Windows; основной контур локальных проверок — отдельное
окружение Python в WSL. Команды ниже выполняются в активированном окружении проекта
из его корня. Версии и правила инструментов следует брать из `pyproject.toml`.

```bash
python -m pytest tests/ -v
python -m ruff check .
python -m ruff format --check .
python -m mypy .
```

Файловые тесты должны использовать синтетические данные и временные каталоги.
Нынешние тесты проверяют отдельные функции именования и парсинга; надёжность
полного pipeline и аварийных файловых операций ими не подтверждена.
Исходники содержат подавления `type: ignore`; успех проверок нужно устанавливать
для конкретной ревизии и окружения, а не считать постоянным свойством проекта.

Правила работы Codex находятся в [AGENTS.md](AGENTS.md).
