# clean_music

Python CLI для очистки музыкальных тегов и имён файлов, нормализации исполнителей,
переименования и обработки предполагаемых дубликатов.

## Состояние и ограничения

При конфликте целевого имени оба файла сохраняются. Safe показывает результаты
анализа дубликатов. Deep удаляет точные копии, если найден единственный файл
с именем, соответствующим тегам по правилу выбора копии.

Изменения поддерживаются только из Windows на локальном NTFS. При сканировании
выбранного каталога допускаются обычные файлы с одной жёсткой ссылкой. Symlink
(включая битые), reparse points, каталоги с аудиорасширением и объекты с ошибкой
проверки пропускаются с причиной. Ссылки и reparse points в пути каталога
тоже приводят к отказу.
Переименование выполняется одним Windows `rename()` внутри каталога без замены
существующей цели. Успех подтверждается по точному написанию записи каталога и
физическому идентификатору исходного файла. Временные имена не используются.
В WSL, в том числе на монтировании диска Windows, доступно чтение коллекции
и отображение кандидатов. Переименование и запись тегов отклоняются с причиной
даже в `--dry-run`. Deep может предложить удаление подтверждённой точной копии
в `--dry-run`; реальное удаление требует Windows и локального NTFS.

Отказ изменения блокирует дальнейшие изменения по исходному пути до конца сессии;
при сбое подтверждения после rename блокируется также целевой путь. Диагностика
показывает запрошенные пути и фактическое местонахождение файла, если его удалось
установить.
Уже записанные перед отказом переименования теги не откатываются.

При сканировании сохраняются идентификаторы тома и файла. Перед переименованием
и записью тегов приложение повторяет проверку исходника и родительского пути.
Если к моменту последней проверки видна подмена или безопасность исходника
не подтверждается, действие пропускается. При модельном переименовании dry-run
проверяется физический исходник. Между последней проверкой и файловой операцией
остаётся окно гонки. Отдельная цель переименования, включая битую ссылку, считается
занятой. Windows rename отказывает и при появлении отдельной цели после проверки.

Безопасный режим сохраняет все аудиофайлы и показывает кандидатов в дубликаты.
Запись тегов, включая ручное заполнение отсутствующих полей, проходит через
проверяемую рабочую копию. При ручном заполнении имеющиеся поля сохраняются,
а ошибки чтения и отказы записи видны в консоли.
См. [контракт двух режимов](docs/architecture.md#контракт-двух-режимов).
Для знакомства используйте отдельную папку с тестовыми копиями. Исходную
коллекцию следует сохранять независимо от программы.

Другие известные ограничения:

- Обрабатывается только выбранная папка, без рекурсивного обхода.
- Изменяются прежде всего исполнитель и название; объединения всех метаданных
  между копиями нет.
- В `--dry-run` каждый этап получает имена и теги после предыдущих
  запланированных операций. При одинаковых исходных данных и ответах прогноз
  описывает успешные действия в пределах доступной проверки. Коллекция,
  настройки и записи восстановления остаются без изменений. Отчёт запуска
  создаётся рядом с программой.
- После запланированного переименования анализ кандидатов использует байты
  исходного файла. После запланированной записи тегов будущий размер и полные
  байты неизвестны, о чём сообщается при сравнении кандидатов.
- Команды меню читаются без учёта регистра. Введённые теги и путь сохраняют регистр.
  На последнем этапе CLI сначала записывает заполненные вручную теги,
  затем предлагает соответствующее имя через файловый исполнитель.

Принятые направления исправления и их статус описаны в
[архитектуре](docs/architecture.md). Они не являются возможностями текущей версии.

## Требования и установка

Требуется Python **3.13 или новее**. `.python-version` выбирает Python 3.13;
uv загрузит его при отсутствии. Зависимости и настройки определены в
`pyproject.toml`, разрешённые версии — в общем для Windows и Linux `uv.lock`.
Приложение запускается из исходного каталога без установки проекта как пакета
(`tool.uv.package = false`).

Один checkout на NTFS используется из двух ОС, но окружения физически раздельны.
Не используйте Windows-окружение из WSL и наоборот. Следующие переменные действуют
в текущей сессии; задавайте их перед работой в новой оболочке. Активация venv
не требуется; если старое окружение активировано, сначала выполните `deactivate`.

### Windows (PowerShell)

Если uv отсутствует, установите его через имеющийся Python без изменения PATH
и политики выполнения PowerShell:

```powershell
python -m pip install uv --target "$env:LOCALAPPDATA\clean_music\uv-bootstrap"
```

Из корня репозитория:

```powershell
$uv = "$env:LOCALAPPDATA\clean_music\uv-bootstrap\bin\uv.exe"
$env:UV_PROJECT_ENVIRONMENT = "$env:LOCALAPPDATA\clean_music\.venv"
& $uv sync --locked
& $uv run --locked python main.py
```

Если uv уже установлен, вместо `& $uv` можно использовать `uv`.

### WSL2 (Bash)

Если uv отсутствует, установите его без изменения профиля и PATH:

```bash
curl -LsSf https://astral.sh/uv/install.sh | env UV_NO_MODIFY_PATH=1 sh
```

В том же репозитории на NTFS (путь при необходимости скорректируйте):

```bash
cd '/mnt/d/Program Files/Dev/clean_music'
export PATH="$HOME/.local/bin:$PATH"
export UV_PROJECT_ENVIRONMENT="$HOME/.cache/clean_music/.venv"
uv sync --locked
uv run --locked python main.py
```

PATH здесь меняется только для текущей сессии. Старое окружение не удаляйте,
пока новая схема не проверена. `sync` по умолчанию включает группу разработки;
для окружения только приложения используйте `uv sync --locked --no-dev`.
Выбирайте выделенный путь: точная синхронизация удаляет лишние пакеты из него.

`uv lock --check` проверяет актуальность lock-файла. Обычная работа использует
`--locked`: несоответствие конфигурации завершится ошибкой без перезаписи lock.
После согласованного изменения зависимостей выполните `uv lock`, проверьте diff
и зафиксируйте `uv.lock` вместе с `pyproject.toml`. Обновление через
`uv lock --upgrade` выполняется только как отдельное согласованное действие.
Справка: [установка uv](https://docs.astral.sh/uv/getting-started/installation/),
[синхронизация](https://docs.astral.sh/uv/concepts/projects/sync/).

## Аварийное восстановление переименований

В Windows на локальном NTFS обычный запуск блокирует выбранный каталог для других
экземпляров clean_music и до сканирования сверяет незавершённые переименования.
Запись в `.clean_music-recovery` появляется перед системным переименованием и
содержит точные имена, идентичность файла, его размер, временные метки и SHA‑256
основного потока. Для этого приложение полностью читает исходный файл.

При следующем запуске приложение подтверждает оригинал под исходным или новым
именем по фактическому состоянию каталога. Занявший прежнее имя чужой файл
сохраняется. Сверка не выполняет повторного переименования или отката. При
неопределённости приложение выводит наблюдения, сохраняет найденные файлы и
служебную запись и блокирует изменения затронутых путей. Если область операции
не установлена или служебный каталог недоступен либо не опознан, обработка
выбранного каталога останавливается. При активном экземпляре повторите запуск
после его завершения. При неопределённости используйте пути и причину из отчёта
для ручной проверки перед возобновлением обработки.

В `--dry-run` и в WSL сверка диагностическая. Она не создаёт служебного состояния
и не изменяет музыкальные файлы. Наблюдения без блокировки могут относиться к
активному процессу. Отчёт запуска по-прежнему создаётся отдельно от коллекции.

Гарантия относится к остановке процесса при продолжающей работать ОС и исправной
файловой системе. Блокировка координирует экземпляры clean_music. Внешние редакторы
могут менять файлы. Устойчивость к потере питания и отказу накопителя не проверялась.

## Безопасная запись тегов

Для реальной записи тегов в Windows установите FFmpeg и добавьте каталог
`ffprobe.exe` в `PATH`. Проверить доступность можно командой `ffprobe -version`.
При первом запросе изменения без `ffprobe` приложение объяснит причину пропуска.
Чтение, анализ и сухой прогон доступны без инструмента. Приложение его не
устанавливает. При совпадающих тегах рабочая копия и запуск `ffprobe` не нужны.

Проверенные профили записи на локальном NTFS:

| Контейнер | Профиль |
| --- | --- |
| MP3 | MPEG Layer III без ID3v1, без ID3 или с обычным ID3v2.4 |
| M4A/MP4 | Нефрагментированный ISO BMFF с одной дорожкой AAC и одним `mdat` |
| FLAC | Native FLAC с Vorbis Comment |
| Vorbis | Ogg Vorbis с одним логическим потоком |
| WMA | ASF с одним потоком WMA v2 без отдельной таблицы языков |

При ошибке чтения, неполной проверке или профиле вне этого набора запись
пропускается. Среди неподтверждённых вариантов — ID3v1/v2.2/v2.3,
ALAC, видео и несколько дорожек, фрагментированный MP4, Ogg FLAC,
цепочки Ogg, DRM и другие варианты WMA. Сохранение аудио проверяется по хешам
пакетов, конфигурации кодека и структуре контейнера. Посторонние поддерживаемые
теги проверяются повторным чтением через Mutagen.

Запись выполняется в независимую рабочую копию. Владелец, группа, DACL и
значимые флаги её наследования проверяются перед переносом содержимого и после
публикации. Сохраняются время создания и атрибуты Hidden, System и Archive.
Время изменения отражает запись готовой копии. При ReadOnly, других
неподдержанных атрибутах, именованных потоках NTFS или невозможности проверить
их отсутствие запись пропускается. Полное сохранение SACL не гарантируется
в обоих режимах. Если для коллекции обязателен аудит или системные метки
безопасности, используйте чтение или сухой прогон.

Журнал #17 также обслуживает запись тегов. Исходное имя может кратковременно
отсутствовать между двумя переименованиями. Оригинал доступен под служебным
именем до подтверждения опубликованной копии. После остановки процесса
сверка может вернуть оригинал под свободное исходное имя или завершить
очистку после подтверждённой публикации. Чужой файл под исходным именем
сохраняется, операция блокируется до разрешения конфликта.

## Запуск

Из корня репозитория:

```powershell
uv run --locked python main.py
uv run --locked python main.py --dry-run
uv run --locked python main.py --debug
```

До запроса пути программа предлагает выбрать режим. При первом запуске и с
сохранённым `safe` нажатие Enter выбирает безопасный режим. Кандидаты в дубликаты
показываются для просмотра, включая причины совпадений и сомнений.

При выборе `deep` и при запуске с таким предпочтением программа предупреждает
о безвозвратном удалении точных дублей. Только команда `run` после предупреждения
запускает deep. Enter или `cancel` в этом меню завершает запуск. Команда `once`
запускает `safe` на один раз, `safe` сохраняет безопасный режим и продолжает запуск, а
`deep` сохраняет предпочтение и завершает запуск. `cancel`, EOF и Ctrl+C во
время выбора завершают запуск до обращения к коллекции.

Реальный deep требует локального NTFS в Windows и отсутствия сторонних изменений
на всём протяжении обработки. Приостановите синхронизацию и другие программы,
способные менять папку. Программа проверяет имена, идентичность объектов,
потоки NTFS и полное побайтовое равенство
перед каждым удалением. Она удерживает победителя и удаляет лишнюю копию по её
открытому дескриптору. Программа не может подтвердить отсутствие сторонних писателей:
конкурент может добавить именованный поток после последней проверки или подменить
имя способом, выходящим за границы проверенной защиты. При первом отказе или
неопределённом результате дальнейшие удаления в группе прекращаются. Уже
подтверждённые удаления необратимы и остаются в отчёте. Аварийное восстановление
охватывает незавершённые переименования и публикацию тегов. Конфликт имени сам по себе
не даёт разрешения удалить файл. В WSL реальное удаление отключено.

Предпочтение хранится в поле `preferred_mode` файла
`%LOCALAPPDATA%\clean_music\settings.json` в Windows. В WSL используется
`$XDG_CONFIG_HOME/clean_music/settings.json` или `~/.config/clean_music/settings.json`
при незаданном `XDG_CONFIG_HOME`. Если настройки недоступны или повреждены,
программа сообщает причину и предлагает безопасный режим.
`--dry-run` применяет выбор только в текущем запуске и не записывает настройки.

Deep с `--dry-run` показывает прогноз. Поздние этапы используют виртуальное
состояние без предложенных к удалению копий. Если будущие байты после виртуальной
записи тегов неизвестны, удаление пропускается. Прогноз не доказывает безопасность
последующего применения изменений.

### Отчёт каждого запуска

CLI автоматически создаёт **один UTF-8 файл** `logs/run-<время UTC>-<id>.log`
рядом с `main.py`. Путь показывается до выбора режима, поэтому отчёт появляется
даже при отмене. После итоговой сверки путь выводится ещё раз.
Вопросы и предложения остаются в терминале; весь диалог, исходные ответы,
выбранные значения по умолчанию, выполненные операции, ошибки и итог сохраняются
в этот же файл. Его можно целиком передать на разбор. `logs/` исключён из Git;
отчёт содержит локальные пути и значения тегов.

До обработки и после неё программа читает SHA-256 и теги исполнителя/названия
аудиофайлов выбранной папки с диска, независимо от кэша конвейера. Большая папка
потребует времени на два полных чтения. Рекурсивного обхода нет; прочие расширения
не проверяются. Ссылки и reparse points не читаются, ошибки проверки фиксируются.

После успешного запуска и полной сверки в начале того же файла появляется
компактный отчёт v3: статус и полнота проверки, режим, commit (или `unknown`, если
Git недоступен), Python/платформа, длительности обработки и сверки, счётчики файлов.
Проблемы показываются первыми: исчезновения, ошибки, отказы и блокировки с причинами,
в том числе «теги записаны, rename отклонён». Для изменённых файлов показаны
дельты имён и artist/title; при переименовании и изменении содержимого без дельты
artist/title показывается пометка `[содержимое]`. Счётчики включают нулевые значения.
Неизменённые перечислены по именам. Структурированные
события связываются с исходными файлами по цепочкам переименований и identity снимков.

В сверке выделены подтверждённое удаление точной копии и неопределённый исход
попытки удаления. Исчезновение файла без подтверждённой операции отражается
отдельно. Замена файлового объекта и ошибки чтения дают ошибку проверки.
Неполные теги показываются с пустым
полем; отсутствие тегов — `null`, ошибки чтения — в `errors`.

В приложении сохранены диалог, структурированные события и объединённые записи
файлов со снимками до и после: полные пути, identity, теги, ошибки и SHA-256.
Структурированные записи представлены JSONL; снимки отдельно не дублируются.
В dry-run события с пометкой `ПРЕДЛОЖЕНИЕ` отделены от факта диска, включая
блокировки модели. Конвейер показывает счётчики запланированных изменений
в сухом запуске и подтверждённых изменений в обычном. Они могут учитывать
несколько операций над одним файлом. Итоговая сверка в `logs/run-*.log`
в обоих режимах читает фактические пути, теги и байты.

Во время работы журнал дописывается без перезаписи. При Ctrl+C, EOF или исключении
он сохраняется и выполняется доступная сверка; остаётся сырой формат с пометкой
прерывания/неполноты. Компактизация не запускается и при неполной сверке.
После успеха файл переформатируется через временный файл в `logs/` и замену
исходного отчёта. При ошибке компактизации остаётся исходный сырой журнал с
предупреждением; временный файл удаляется, если файловая система позволяет.
Принудительное завершение процесса, сбой питания или потеря диска могут оставить
только начатый журнал без итогов. Если лог невозможно создать, обработка не начинается;
ошибка записи журнала прерывает запуск. Отчёт не является резервной копией и не
откатывает изменения. SHA-256 всего файла меняется при записи тегов и не проверяет
аудиопоток отдельно; правильность текста тегов и защиту от конкурентных изменений
другими программами отчёт не гарантирует.

## Поддерживаемые форматы

Обработчики реализованы для MP3, M4A/MP4, FLAC, OGG Vorbis и WMA.
Поддержка расширения или контейнера не означает поддержку любого содержащегося
в нём кодека; для OGG используется обработчик Vorbis. Расширение само по себе
не определяет качество аудио.

## Текущий pipeline

Последовательно выполняются семь этапов:

1. Очистка мусорных вставок из имён и тегов.
2. Нормализация тире и пробелов в именах.
3. Нормализация `feat.`, разделителей и уточнений; переименование по тегам.
4. Запись тегов из распознанного имени файла.
5. Анализ групп кандидатов и удаление подтверждённых точных копий в deep.
6. Унификация вариантов регистра имён исполнителей.
7. Ручной ввод исполнителя для оставшихся файлов без распознанных тегов.

Оркестратор находится в `pipeline.py`, этапы — в `stages.py`.
Подробности компонентов и ограничения контракта путей — в
[описании реализованной архитектуры](docs/architecture.md#реализовано).

## Разработка и проверки

Основная рабочая среда — Windows; основной контур локальных проверок — отдельное
окружение Python в WSL. Команды ниже выполняются из корня после выбора
`UV_PROJECT_ENVIRONMENT` и `uv sync --locked`, описанных выше. В PowerShell
с установкой через pip заменяйте `uv` на `& $uv`.

```bash
uv run --locked python -m pytest tests/ -v
uv run --locked python -m ruff check .
uv run --locked python -m ruff format --check .
uv run --locked python -m mypy .
```

Файловые тесты должны использовать синтетические данные и временные каталоги.
Нынешние тесты проверяют отдельные функции именования и парсинга; надёжность
полного pipeline и аварийных файловых операций ими не подтверждена.
Исходники содержат подавления `type: ignore`; успех проверок нужно устанавливать
для конкретной ревизии и окружения, а не считать постоянным свойством проекта.

Правила работы Codex находятся в [AGENTS.md](AGENTS.md).
